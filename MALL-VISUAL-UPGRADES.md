# Mall visual-upgrade programme

This is the execution board for the mall’s graphics pass. `MALL-TODO.md` remains the project’s
machine-generated product checklist; this file owns visual implementation and evidence. The board
is intentionally large, but every row is bounded and testable.

Status: `[ ]` ready, `[~]` landed or in progress but not fully proven, `[x]` accepted with evidence,
`[!]` blocked by a named dependency. Priority: P0 before P1; P2 only after measured headroom.

The engineering loop is strict:

1. Take the lowest ready item whose dependencies are complete. Work in disjoint files when parallel.
2. Keep the 60 fps rule, invented-brand rule, +60-static-prop tenant ceiling, and existing peak-rig
   ceiling. A visual gain that misses the performance gate is reverted.
3. Run narrow source/logic checks, capture the declared before/after view, inspect it, then run the
   relevant collision and performance gates.
4. Change `[ ]` to `[x]` only with concrete evidence in the last column. Source present is `[~]`, not
   complete. Run `node .mallvisualplancheck.js --require-complete` for the final gate.
